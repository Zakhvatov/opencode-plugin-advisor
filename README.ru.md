# opencode-plugin-advisor

[English](README.md) · [Русский](README.ru.md)

Вторая модель, которая смотрит за каждым шагом сессии [OpenCode](https://opencode.ai).

Адвайзер читает приращение транскрипта основного агента, проверяет репозиторий read-only инструментами и возвращает в основную сессию короткие заметки `<advisory>`. Это порт подсистемы адвайзера из [oh-my-pi](https://github.com/can1357/oh-my-pi) (`WATCHDOG.md`, `WATCHDOG.yml`, инструмент `advise`, маршрутизация по важности и защитный фильтр вывода) на плагинный API OpenCode V2.

> Решает основной агент. Адвайзер предлагает взгляд, поднимает проблему или блокирует работу, которая вот-вот сломается. Файлы он не редактирует.

```text
основная сессия ── приращение шага ──▶ сессия адвайзера ── read / grep / glob ──▶ advise(note, severity)
       ▲                                                                               │
       └─────────────────── синтетическая заметка <advisory> ◀──── фильтр ◀────────────┘
```

## Зачем

Агент, который проверяет свою же работу, слеп ровно там, где эту работу и делал. Вторая модель со своим контекстом, своей моделью и read-only набором инструментов ловит то, мимо чего исполнитель проскочил: неверное допущение, забытое ограничение, «готово», которое никто не запускал.

Адвайзер намеренно молчалив. Тишина — это нормальный результат: если проверять нечего, он ничего не отправляет.

## Требования

- OpenCode **V2** (`opencode` 2.4 или новее; разработка шла на 2.4.2)
- Провайдер и модель для адвайзера. Лучше взять модель, отличную от основной, но это не обязательно.

## Установка

Пакета пока нет в npm. Укажите OpenCode на этот каталог:

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "/абсолютный/путь/к/opencode-plugin-advisor",
      "options": {
        "model": "anthropic/claude-sonnet-4-5",
        "reviewMode": "turn"
      }
    }
  ]
}
```

Можно поставить и в проект — в `.opencode/plugins/`, добавив пакет в `plugins`.

После публикации установка будет такой:

```sh
opencode plugin add opencode-plugin-advisor
```

## Настройка

Все параметры необязательны, кроме `model`: если его не указать, адвайзер возьмёт модель основной сессии.

```jsonc
{
  "plugins": [
    {
      "package": "opencode-plugin-advisor",
      "options": {
        "model": "anthropic/claude-sonnet-4-5#high",
        "reviewMode": "turn",
        "reviewInterval": 1,
        "maxNotesPerUpdate": 4,
        "continueSeverity": "concern",
        "tools": ["read", "grep", "glob"],
        "includeReasoning": true,
        "scope": "main",
        "watchdog": true,
        "instructions": "Особое внимание — границам транзакций в src/db/.",
        "debug": false
      }
    }
  ]
}
```

| Параметр | По умолчанию | Значение |
| --- | --- | --- |
| `enabled` | `true` | Включить подсистему адвайзера. |
| `model` | модель основной сессии | Модель адвайзера в виде `provider/model` с необязательным `#variant`. |
| `reviewMode` | `"turn"` | `turn` — проверять каждый шаг ассистента; `agent-end` — только финальные шаги и переходы в простой. |
| `reviewInterval` | `1` | Проверять каждое N-е подходящее обновление. Пропущенные обновления попадут в следующую проверку. |
| `maxNotesPerUpdate` | `4` | Сколько заметок без блокеров принимается за проверку (`1`–`32`). Блокеры в лимит не входят. |
| `continueSeverity` | `"concern"` | Минимальная важность, при которой можно разбудить простаивающую основную сессию ради одного продолжения. |
| `tools` | `["read","grep","glob"]` | Read-only инструменты, выданные адвайзеру. |
| `instructions` | `""` | Дополнительные указания только для адвайзера, дописываются после `WATCHDOG.md`. |
| `includeReasoning` | `true` | Включать блоки рассуждений основной модели в проверяемое приращение. |
| `scope` | `"main"` | `main` — следить только за сессиями верхнего уровня; `all` — ещё и за сессиями сабагентов. |
| `watchdog` | `true` | Подмешивать файлы `WATCHDOG.md` в промпт адвайзера. |
| `minReviewGapMs` | `0` | Минимальный интервал между проверками одной сессии. |
| `maxReviewsPerRun` | `30` | Предохранитель на один прогон основной сессии; сбрасывается новым сообщением пользователя. |
| `reviewTimeoutMs` | `120000` | Прервать шаг адвайзера, который идёт дольше этого времени. |
| `initialReplay` | `20` | Сколько сообщений проигрывать при старте курсора или перезаписи транскрипта. |
| `debug` | `false` | Писать жизненный цикл адвайзера в лог сервера OpenCode. |

Если задать `ADVISOR_DEBUG_FILE=/абсолютный/путь.log`, отладочные строки будут дублироваться в файл — удобно для headless-прогонов и тестов.

## Что смотреть: `WATCHDOG.md`

`WATCHDOG.md` — подсказки только для адвайзера. Файл добавляется в его системный промпт и никогда не попадает к основному агенту. Сюда пишут приоритеты проверки, проектные ловушки и опасные API.

Порядок поиска:

1. `~/.config/opencode/WATCHDOG.md` (или `$XDG_CONFIG_HOME/opencode/WATCHDOG.md`)
2. Все `WATCHDOG.md` и `.opencode/WATCHDOG.md` от корня проекта вниз до каталога сессии

```markdown
# Заметки для надзора

Особенно смотреть за:

- Изменениями, которые обходят надёжную очередь в `src/jobs/`.
- UI-путями, которые рендерят вывод инструментов без санитайза.
- Новыми воркерами, которые не переиспользуют хост CLI.
```

Импорты `@path` пока не разворачиваются.

## Важности и доставка

Адвайзер вызывает `advise({ note, severity })`:

| Важность | Доставка |
| --- | --- |
| `nit` (или без важности) | Подмешивается в следующий вызов модели, если основная сессия работает; иначе ждёт в очереди до следующего сообщения пользователя. |
| `concern` | Как `nit`, пока идёт прогон; при `continueSeverity` не выше `concern` будит простаивающую основную сессию на одно продолжение. |
| `blocker` | Как `concern`, но не тратит бюджет заметок на проверку и не подчиняется паузе для `concern`. |

Заметки попадают в транскрипт основной сессии в таком виде:

```text
<advisory severity="concern" guidance="weigh, don't blindly obey">
Миграция удаляет индекс до коммита транзакции.
</advisory>
```

Продолжение, вызванное адвайзером, не взводит себя заново. Адвайзер продолжает проверять ответ основного агента, но разбудить сессию снова сможет только настоящее сообщение пользователя.

## Защитный фильтр (emission guard)

Промпт просит качества, а фильтр делает его обязательным:

- Пустые и бессодержательные заметки (`stop`, `done`, `lgtm`, `no issue continue`, …) отбрасываются.
- Повторы той же или меньшей важности отбрасываются; строго более высокая важность — это настоящее усиление.
- Заметки без блокеров ограничены на одну проверку. `concern` может вытеснить ожидающий `nit` из той же проверки; на блокер лимит не действует.
- На каждую отклонённую заметку адвайзер получает честный ответ в результате инструмента.

## Команды

```text
/advisor          статус
/advisor status   статус
/advisor on       включить для этой сессии
/advisor off      выключить и прервать адвайзера
```

В статусе видно модель адвайзера, частоту проверок, их число, id сессии адвайзера и последнюю ошибку.

## Как это соотносится с oh-my-pi

| oh-my-pi | Здесь |
| --- | --- |
| роль модели `advisor` | опция плагина `model` |
| `advisor.enabled` | опция `enabled` и `/advisor on|off` |
| `WATCHDOG.md` | тот же порядок поиска, но под каталогом конфигурации OpenCode |
| реестр `WATCHDOG.yml` | пока не портирован; один адвайзер на сессию |
| `reviewMode` | та же семантика `turn` / `agent-end` |
| `reviewInterval` | так же, пропущенные приращения попадают в следующую проверку |
| инструмент `advise` | тот же инструмент, та же шкала важности, тот же фильтр |
| `maxNotesPerUpdate` | тот же бюджет, включая вытеснение по рангу |
| файл транскрипта адвайзера | настоящая архивная сессия OpenCode с именем `[advisor] <primary>` |
| `advisor.syncBacklog` | не портирован; в OpenCode нет блокирующего хука догоняния |
| резервный ревьюер и цепочки fallback | не портированы; используйте fallback провайдеров OpenCode |

Заметки по чтению оригинальной реализации — в [`docs/omp-advisor.md`](docs/omp-advisor.md).

## Цена и задержка

Каждая проверка — это настоящий шаг модели в отдельной сессии. В режиме `turn` длинный цикл инструментов даёт много проверок. Управлять этим можно так:

- `reviewMode: "agent-end"` — одна проверка на прогон;
- `reviewInterval: 2` или `3` — проверять каждый N-й шаг;
- `minReviewGapMs` — задать минимальный интервал по времени;
- `maxReviewsPerRun` — жёсткий потолок;
- дешёвая модель адвайзера или сильная только там, где она окупается.

При `opencode run` (headless) процесс может завершиться, как только основная сессия простаивает. Проверки в середине прогона успевают, финальная проверка `agent-end` может оборваться. Для headless-прогонов используйте режим `turn`.

## Разработка

```sh
bun install
bun run check     # проверка типов + юнит-тесты
```

Интеграционный стенд, на котором шла разработка, живёт вне этого репозитория: временный проект с `opencode.json`, указывающим на этот каталог, бесплатная модель и `ADVISOR_DEBUG_FILE` для диагностики.
